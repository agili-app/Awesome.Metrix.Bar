# Design System

Awesome.Metrix.Bar follows the visual language of [panda-css.com](https://panda-css.com/): a yellow hero band, ink
outlines with a hard offset shadow on primary actions, quiet 1px cards, mono uppercase eyebrows, and ink links with an
accent underline. This file records intent. Token values are generated, not copied here.

## Where things live

| Layer            | File                                            | Holds                                                                                                                      |
| ---------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Primitive tokens | `theme/tokens.ts`                               | Additions to `@pandacss/preset-panda`: `colors.ink`, `blackAlpha`/`whiteAlpha`, `borderWidths.thin/thick`, `radii.control` |
| Semantic tokens  | `theme/semantic-tokens.ts`                      | Every color role and its light/dark pair; `shadows.offset`                                                                 |
| Composite styles | `theme/text-styles.ts`, `theme/layer-styles.ts` | Typography roles and surfaces                                                                                              |
| Recipes          | `theme/recipes/`                                | `button`, `textLink`, `badge`, and the `card` slot recipe                                                                  |
| ui-sdk theme     | `theme/ui-sdk.ts`                               | Maps `@ui-sdk/core/web.css` `--ui-*` tokens to Panda tokens and overrides signature parts, Timeline, and Waterfall         |
| Global styles    | `theme/global-css.ts`                           | Canvas, focus ring, selection, reduced motion, and `uiSdkGlobalCss`                                                        |
| Assembly         | `panda.config.ts`                               | Presets, conditions, and the imports above                                                                                 |
| Internal gallery | `design/`                                       | Local-only showcase (`http://localhost:2937/__design` during `vp dev`), excluded from the site build and deployment        |

Resolved values, CSS variables, and recipe variants are in `styled-system/specs/design-system.json`, regenerated by
`vp run styles` and `vp run types`. Read that file for values instead of this one or the config.

## Principles

- **Loud once, quiet everywhere else.** The funky treatment (thick ink border, offset shadow, `control` radius) marks the
  one primary panel or action in a region. Repeated items such as catalog cards stay 1px and flat.
- **Hover never moves layout.** Funky elements grow their shadow; everything else changes only background or color.
- **Color by role.** Components use semantic tokens. Light and dark are decided in `theme/semantic-tokens.ts`; `_dark`
  does not appear in components.
- **System fonts.** No web fonts are loaded, so every supported language renders with native glyphs. Mono is reserved
  for eyebrows, badges, IDs, and hashes.
- **Content without JavaScript.** Styling must never depend on client scripts; interactive enhancements are optional.

## Color roles

| Token                                  | Use for                                                                  |
| -------------------------------------- | ------------------------------------------------------------------------ |
| `bg`                                   | Page canvas                                                              |
| `bg.surface`                           | Panels and cards that sit on the canvas                                  |
| `bg.subtle`                            | Card hover, inset code and inputs                                        |
| `bg.muted`, `bg.muted.hover`           | Image wells, menu item hover, thumbnails                                 |
| `bg.main`                              | The hero band, and the header above it on the homepage                   |
| `bg.emphasized`, `bg.emphasized.hover` | Emphasized action surface on dark or yellow backgrounds                  |
| `bg.inverted` / `fg.inverted`          | Solid badges                                                             |
| `bg.overlay`                           | Modal and lightbox backdrop scrim                                        |
| `fg`                                   | Body text and link text                                                  |
| `fg.muted`                             | Secondary copy, descriptions, metadata                                   |
| `fg.subtle`                            | Tertiary labels: separators, counts, definition terms                    |
| `fg.headline`                          | `h1` display text only                                                   |
| `fg.onAccent`                          | Text on `accent` fills                                                   |
| `accent`                               | Primary button fill, brand mark, checked/selected control fills          |
| `accent.emphasis`                      | Link underline                                                           |
| `accent.subtle`                        | Text selection, highlighted popup/list items                             |
| `accent.wash`                          | Link hover, current menu item, current thumbnail, selected rows          |
| `link`, `link.emphasized`              | Inline prose or code-highlight accent links when blue is needed          |
| `border`                               | Default 1px dividers and card edges                                      |
| `border.muted`                         | Hairlines inside an already bordered surface                             |
| `border.ink`                           | Funky outlines, input/control edges, and the offset shadow color         |
| `danger`                               | Errors, destructive actions, and invalid control borders                 |
| `focusRing`                            | Keyboard focus outline and focused input border (ink light, yellow dark) |

Primitive scales (`neutral.600`, `yellow.300`) are not used in components. The sole exception is the white backing behind
dashboard icons, which are drawn for light backgrounds.

## Typography

| Text style | Use for                                                        |
| ---------- | -------------------------------------------------------------- |
| `display`  | The single `h1` of a page                                      |
| `lead`     | The paragraph directly under `display`                         |
| `heading`  | Section `h2`                                                   |
| `title`    | Card and dialog titles                                         |
| `eyebrow`  | Kickers above headings, field labels, counts, definition terms |

Negative tracking is reset under the `_cjk` condition (`zh`, `ja`, `ko`) so CJK text keeps its natural spacing. Body copy
uses the global `1.65` line height; don't override it per paragraph.

## Surfaces

- `layerStyle: "offShadow"`: primary panels (hero registry panel, install panel, lightbox dialog). At most one per
  viewport region.
- `layerStyle: "card"`: secondary panels (dashboard details, language menu). Add `boxShadow: "lg"` only for floating
  menus.

## Recipes

| Recipe     | Variants                                                                                 | Use                                                                                                                                                                                  |
| ---------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `button`   | `visual`: `main` (default), `secondary`, `outline`; `size`: `md` (default), `sm`, `icon` | `main` for the one primary action, `secondary` for its sibling, `outline` for repeated or utility actions. Render install and download actions as native `<a>` through `ActionLink`. |
| `textLink` | `tone`: `default`, `muted`                                                               | Every inline or standalone text link. `muted` for footer, breadcrumb, and metadata links. Navigation bar links are styled in place instead.                                          |
| `badge`    | `visual`: `outline` (default), `solid`                                                   | Categories and counters. `solid` only when the badge overlays an image.                                                                                                              |
| `card`     | Slots: `root`, `header`, `title`, `meta`, `body`, `footer`                               | Catalog entries. Keep the `dashboard-card` hook class next to `card().root`.                                                                                                         |

Promote a style to a recipe only when a second file needs it; single-use styles stay in `css()` at the call site.

## ui-sdk integration

`src/views/site.css` imports `@ui-sdk/core/web.css` into a dedicated `ui-sdk-web` layer placed between Panda's `reset`
and `base` layers (`@layer reset, ui-sdk-web; @layer reset, base, tokens, recipes, utilities;`). That keeps ui-sdk's
default component styles intact above preflight while `theme/ui-sdk.ts` (in `base`), project recipes (in `recipes`), and
`css()` overrides (in `utilities`) win cleanly without `!important`.

`theme/ui-sdk.ts` maps every `--ui-*` variable to semantic tokens, styles signature states (`data-variant="solid"`,
checked/pressed/highlighted/selected states, modals, drawers, toasts, calendars, pagination), and provides complete
styles for `Timeline` and `Waterfall` (which `web.css` leaves unstyled). Open `http://localhost:2937/__design` while
running `vp dev` to inspect every component in light and dark mode.

## Don'ts

- Don't add `_dark` or primitive colors at call sites; add or adjust a semantic token.
- Don't put the funky treatment on list items, or animate `transform` on hover.
- Don't load web fonts or set a fixed root font size; user font settings must apply.
- Don't remove hook classes or `data-*` attributes used by scripts and verification (`dashboard-card`,
  `project-stars`, `dashboard-preview-cover`, `data-preview-*`, `data-prefetch`, `data-agent-action`).
